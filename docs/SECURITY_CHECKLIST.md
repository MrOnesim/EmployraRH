# Security & CI Checklist for EmployraRH

This document collects immediate security, CI and E2E recommendations observed during the audit.

1) CI: ensure Prisma client is generated before building
- Rationale: Type-safe generated @prisma/client types and runtime artifacts must exist before TypeScript build or Nest build.
- Action already applied: add `npx prisma generate` step in the backend CI job (see .github/workflows/ci.yml).

2) Dependency vulnerabilities
- Run `npm audit` in both project root and backend and review vulnerabilities.
- Run `npm audit fix` and `npm audit fix --force` only after reviewing breaking changes.
- Prioritize replacing or upgrading deprecated/archived packages (example: `csurf` is archived).
- Consider adding dependabot or Renovate to automatically open PRs for dependency updates.

3) Secrets and environment variables
- Never commit real secrets. Keep `.env.example` for documentation only.
- Ensure CI secrets are stored in GitHub Actions secrets and not printed in logs.
- Use scoped service accounts for production credentials.

4) Content Security Policy (CSP)
- Current code disables CSP in Helmet (contentSecurityPolicy: false). Add a strict CSP in production to mitigate XSS risks.
- Example approach: maintain a production CSP string in env/config and apply only in production.

5) CSRF protection
- The codebase uses a custom CSRF approach and `csurf` is present but archived. Evaluate migration to maintained alternatives or keep custom implementation but review carefully.

6) Sentry & error reporting
- Ensure SENTRY_DSN is only set in production (via env/CI secrets) and errors do not leak sensitive data.
- Scrub PII before sending to Sentry if necessary.

7) Logging and debug
- Replace console.log in backend with NestJS Logger or a structured logger. Avoid logging secrets.

8) Tests & E2E
- Playwright is configured to start the dev server via `npm run dev`. In CI the workflow already installs playwright and runs `npx playwright test`.
- Ensure E2E tests run against a reproducible environment (test DB, seeded data). Prefer running E2E inside Docker or use dedicated test DB.

9) Prisma & DB
- Add `npx prisma generate` to CI (done) and to any build scripts that run in ephemeral environments.
- Consider running `prisma migrate deploy` in production and `prisma db push` only in non-critical environments.

10) Automation suggestions
- Add GitHub Actions job for `npm audit` on a schedule and/or enable dependabot.
- Add a CI step to run `npx prisma generate` and `npx prisma validate` before the build.

11) Quick remediation tasks
- Upgrade `uuid`, `glob`, and investigate `csurf` alternatives.
- Run `npm audit` and triage the `high` vulnerabilities.
- Add `prisma generate` to backend build steps in CI (applied).
- Add a security.md or update README with required env vars and guidance for secrets (this file complements README).
